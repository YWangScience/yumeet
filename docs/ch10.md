# 第 10 章 · API 与开放集成

yuMeet 是 API-first 的:管理后台与公共站点消费的每一个能力,都以同样的接口暴露给第三方。本章定义四层接口面(内部进程内调用、对外 REST、Webhooks、开放数据),给出可直接照抄的请求示例、完整 webhook 事件表与签名校验实现,并列出核心第三方集成的机制与数据流向。

## 10.1 API-first:内部进程内调用、对外 REST、鉴权与版本化

业务逻辑唯一实现于 packages/core:apps/web 的页面数据操作经 Server Actions 进程内调用 core,apps/api 与 apps/worker 同样直接 import core——业务逻辑只写一遍,类型安全由 monorepo 共享类型保证,不需要任何 RPC 胶水层。apps/api(Fastify)的职责收窄为三件事:① 对外开放 REST API(OpenAPI 3.1、API key、限流),作为第三方集成与高并发报名/抢票流量的入口,可独立水平扩容;② 实时长连接(SSE 公告、Yjs 协作 WebSocket);③ 插件 HTTP 挂载点(Fastify plugin/hook 体系是第 13 章插件架构的宿主)。对外接口的单一事实来源是 Zod schema:每个路由的输入输出都以 Zod 定义,fastify-zod-openapi 将同一份 schema 编译为 OpenAPI 3.1 文档。文档在 `/api/v1/openapi.json` 提供机器可读版本,在 `/docs/api` 提供交互式浏览。这意味着「文档过期」在结构上不可能发生——文档就是校验器本身。

| 接口面 | 消费者 | 协议与形态 | 稳定性承诺 |
| --- | --- | --- | --- |
| Server Actions + packages/core | apps/web(RSC 与客户端组件) | 进程内函数调用,无网络胶水,类型随 monorepo 同步 | 无外部承诺,随版本自由重构 |
| REST `/api/v1` | 第三方系统、脚本、移动端 | JSON over HTTPS,OpenAPI 3.1 描述 | 加性变更不破坏;破坏性变更走 `/api/v2` |
| Webhooks | 第三方系统(被动接收) | HTTPS POST + HMAC 签名 | 事件类型只增不改;payload 字段只增不删 |
| 开放数据 | 日历客户端、搜索引擎、RSS 阅读器 | ICS / JSON-LD / Atom,免鉴权 | 遵循各自开放标准 |

对外 REST 的鉴权支持两种凭证。**API key** 面向服务器到服务器场景:格式 `pdm_live_` / `pdm_test_` 前缀加 32 字节随机串,归属组织、由组织管理员在 `/manage/{org}/settings/api` 创建,创建时勾选 scope,存储侧只保留 SHA-256 摘要(见第 12 章)。**OAuth 2.0 应用** 面向代表用户操作的第三方产品:authorization code + PKCE,refresh token 旋转,scope 与 API key 共用同一张表。两种凭证都受按 key 的速率限制(默认 600 req/min,可在后台调整)。

| scope | 授权范围 |
| --- | --- |
| `events:read` / `events:write` | 读取/创建修改活动、日程、场地 |
| `registrations:read` / `registrations:write` | 读取/创建修改报名与签到(read 包含参会者个人信息,受第 12 章数据最小化约束) |
| `submissions:read` / `submissions:write` | 读取/创建修改投稿与评审 |
| `orders:read` | 读取订单与支付状态(退款需 `orders:refund`) |
| `files:read` / `files:write` | 资料库文件的签名 URL 获取与上传 |
| `webhooks:manage` | 创建、暂停、删除 webhook endpoint |

**版本化策略**:路径版本(`/api/v1`)+ 日期化行为版本。加字段、加端点、加枚举值属于非破坏变更,直接发布;改字段语义或删除属于破坏变更,进入 `/api/v2`。废弃的端点至少保留 12 个月,期间响应携带 `Deprecation` 与 `Sunset` 头,并在管理后台的 API 用量页对仍在调用的 key 逐个提示。Webhook payload 的行为版本由 endpoint 上的 `api_version`(如 `2026-08-01`)钉住,升级由集成方主动触发。

## 10.2 资源设计与请求示例

REST 资源设计遵循以下规则,全部端点无例外:

1. 资源名用复数名词,层级最多两层:`/api/v1/events/{event_id}/registrations`;更深的关系用查询参数表达。
2. 所有对象 ID 是带类型前缀的编码 ID(`evt_`、`reg_`、`sub_`、`ord_`、`tkt_` 等前缀 + 内部 UUIDv7 主键的 Crockford base32 编码,字段定义见第 9 章),前缀让日志与报错自带类型信息。
3. 列表一律 cursor 分页:`limit`(默认 20,上限 100)+ `cursor`,响应含 `pagination.next_cursor` 与 `has_more`;不提供 offset 分页。
4. 时间戳一律 RFC 3339 UTC(`Z` 后缀),由客户端按时区渲染。
5. 写操作支持 `Idempotency-Key` 头,24 小时内同 key 重放返回首次响应并附 `Idempotency-Replayed: true`(与第 13 章抢票路径共用同一实现)。
6. 错误响应统一为 RFC 9457 `application/problem+json`,永远携带 `request_id` 供排障对账。

## 10.3 Webhooks

组织管理员在 `/manage/{org}/settings/webhooks`(或通过 `webhooks:manage` scope 的 API)注册 endpoint:填 URL、勾选订阅事件、获得一次性展示的 `whsec_` 签名密钥。投递由 apps/worker 的 BullMQ 队列执行,与请求路径完全解耦——任何业务写操作只负责落一条 outbox 记录,不因订阅方宕机而变慢。

| 事件类型 | 触发时机 | `data.object` |
| --- | --- | --- |
| `event.created` | 活动创建(草稿态) | event |
| `event.published` | 活动发布上线 | event |
| `event.updated` | 活动基本信息变更 | event |
| `event.archived` | 活动进入归档态 | event |
| `registration.created` | 新报名提交 | registration |
| `registration.pending_review` | 报名进入人工审批队列 | registration |
| `registration.confirmed` | 审批通过或支付完成,报名确认 | registration |
| `registration.waitlisted` | 名额满,进入候补 | registration |
| `registration.promoted` | 候补转正 | registration |
| `registration.cancelled` | 参会者或组织者取消报名 | registration |
| `registration.checked_in` | 现场签到完成 | registration |
| `order.created` | 订单创建,待支付 | order |
| `order.paid` | 支付成功 | order |
| `order.refunded` | 退款完成(含部分退款) | order |
| `order.expired` | 支付超时,库存释放 | order |
| `submission.created` | 新投稿提交 | submission |
| `submission.updated` | 投稿人修改稿件 | submission |
| `submission.withdrawn` | 投稿人撤稿 | submission |
| `submission.accepted` | 录用决定发布:接收 | submission |
| `submission.rejected` | 录用决定发布:拒绝 | submission |
| `review.submitted` | 审稿人提交评分(双盲下不含身份字段) | review |
| `schedule.published` | 日程版本首次发布 | schedule_version |
| `schedule.updated` | 已发布日程变更(同步递增 ICS SEQUENCE) | schedule_version |
| `email.bounced` | 邮件硬退信 | email_delivery |
| `email.complained` | 收件人标记垃圾邮件 | email_delivery |

投递体是统一信封,`id` 是投递级唯一 ID(重试不变),消费方以它做幂等去重;事件间不保证顺序,消费方应以 `created_at` 与对象自身状态为准:

```json
{
  "id": "whd_01J5R2K8QW3ND7",
  "type": "registration.confirmed",
  "api_version": "2026-08-01",
  "created_at": "2026-08-17T09:30:02Z",
  "data": {
    "object": {
      "id": "reg_01J5R19M6VXW2P",
      "event_id": "evt_01J5QW8PH3ZKQ4",
      "status": "confirmed",
      "ticket_id": "tkt_01J5QX2R7DQGVN"
    }
  }
}
```

**HMAC 签名**:每次投递携带 `yuMeet-Signature: t=1755423002,v1=5f8a…` 头。签名串是 ``${t}.${rawBody}``,算法 HMAC-SHA256,密钥为该 endpoint 的 `whsec_`。校验方必须:用原始字节而非重新序列化的 JSON;拒绝时间戳偏差超过 300 秒的请求(防重放);用常数时间比较(防时序侧信道):

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

const TOLERANCE_SECONDS = 300;

export function verifyyuMeetSignature(opts: {
  rawBody: string; // 必须是原始请求体字节串,不能 JSON.parse 后再 stringify
  header: string;  // yuMeet-Signature 头的完整值
  secret: string;  // whsec_ 开头的 endpoint 密钥
}): boolean {
  const parts = Object.fromEntries(
    opts.header.split(",").map((kv) => kv.split("=", 2) as [string, string]),
  );
  const t = Number(parts["t"]);
  const v1 = parts["v1"] ?? "";
  if (!Number.isFinite(t)) return false;
  if (Math.abs(Date.now() / 1000 - t) > TOLERANCE_SECONDS) return false;

  const expected = createHmac("sha256", opts.secret)
    .update(`${t}.${opts.rawBody}`)
    .digest("hex");
  const a = Buffer.from(expected, "hex");
  const b = Buffer.from(v1, "hex");
  return a.length === b.length && timingSafeEqual(a, b);
}
```

**重试与死信**:响应 2xx 且在 10 秒内返回视为成功;否则按下表指数退避重试,共 8 次:

| 尝试 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 距上次间隔 | 立即 | 30s | 2m | 10m | 30m | 2h | 6h | 12h |

8 次全部失败后投递进入死信队列,在管理后台的 webhook 详情页可见完整请求/响应记录,支持单条或按时间范围手动重投。一个 endpoint 连续 5 天所有投递均失败时自动暂停,并邮件通知组织管理员;暂停期间事件继续落 outbox,恢复后可补投最近 30 天。

## 10.4 开放数据:ICS、JSON-LD、RSS

公开活动的数据默认以三种免鉴权格式对外开放(活动可见性为 unlisted/private 时自动关闭)。这是「归档是一等公民」原则在接口层的体现:活动结束后这些 URL 永久有效。

**ICS 订阅**:每个活动提供 `/{event-slug}/calendar.ics`(全部日程)与 `?track=`、`?room=` 过滤;每个参会者在状态追踪页拿到含个人 token 的 `/me/calendar.ics`(只含自己报名的场次,见第 5 章)。日程变更时对应 VEVENT 的 `SEQUENCE` 递增,日历客户端据此更新已导入条目;响应支持 ETag/304,轮询成本趋零:

```http
GET /open-science-days-2026/calendar.ics HTTP/1.1
If-None-Match: "v7-a41c"

HTTP/1.1 200 OK
Content-Type: text/calendar; charset=utf-8
ETag: "v8-9d2e"
Cache-Control: public, max-age=300

BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//yuMeet//EN
METHOD:PUBLISH
BEGIN:VEVENT
UID:blk_01J5QYA2QKW3MF@events.example.org
SEQUENCE:3
DTSTART:20261109T080000Z
DTEND:20261109T090000Z
SUMMARY:Opening Keynote
LOCATION:Auditorium A
END:VEVENT
END:VCALENDAR
```

**schema.org JSON-LD**:每个公开活动页由 Next.js Metadata API 注入一段 `application/ld+json`,让 Google 富结果与聚合站直接收录活动。生成内容示例:

```json
{
  "@context": "https://schema.org",

  "name": "Open Science Days 2026",

  "endDate": "2026-11-11T18:00:00+01:00",

  "eventStatus": "https://schema.org/EventScheduled",
  "location": {
    "@type": "Place",
    "name": "Kongresshaus Zurich",
    "address": { "@type": "PostalAddress", "addressLocality": "Zurich", "addressCountry": "CH" }
  },
  "organizer": { "@type": "Organization", "name": "Example Institute", "url": "https://events.example.org" },
  "offers": {
    "@type": "Offer",
    "price": "120.00",

    "url": "https://events.example.org/open-science-days-2026/register"
```

**RSS/Atom**:组织级 `/{org}/feed.xml` 输出最近发布的活动,条目在活动发布与日程发布时更新。三种格式都由 ISR 页面同一渲染管线产出,缓存失效策略见第 13 章。

## 10.5 第三方集成

| 集成 | 形态 | 机制 | 数据方向 |
| --- | --- | --- | --- |
| Stripe | 核心插件 | Checkout Session + 入站 webhook | 双向 |
| 微信支付 / 支付宝 | 社区插件 | Native 支付 / 当面付 + 异步通知 | 双向 |
| Google / Outlook 日历 | 内建 | add-to-calendar 深链 + ICS 订阅(10.4) | 输出 |
| Zoom / Google Meet | 核心插件 | OAuth 应用,按 session 建会并回写 join_url | 双向 |
| Slack / 飞书 / 钉钉 | 核心插件 | incoming webhook 机器人,订阅 10.3 事件转发为卡片消息 | 输出 |

**Stripe** 是支付的参考实现(产品层配置见第 4 章,插件扩展点见第 13 章),写路径如下:

1. 报名提交,api 创建 `order`(状态 `pending`)并预留库存,过期时间默认 30 分钟。
2. api 创建 Stripe Checkout Session,`client_reference_id` 填 `ord_` ID,参会者跳转支付。
3. Stripe 回调 `/api/v1/integrations/stripe/webhook`,worker 校验 Stripe 签名后按 Stripe 事件 ID 幂等消费 `checkout.session.completed`。
4. 订单置 `paid`,报名状态机推进到 `confirmed`,触发确认邮件与 `order.paid`、`registration.confirmed` 出站 webhook。
5. 超时未支付由 worker 定时任务置 `expired` 并释放库存(高并发时序见第 13 章)。

**会议软件**:组织管理员连接 Zoom 或 Google OAuth 账号后,日程编排器中任一 session 可勾选「自动创建线上会议」;worker 调用对方 API 建会,把 `join_url` 写回 session,公共页对已报名者渐进展示(见第 5 章线上与混合)。**IM 通知**:Slack/飞书/钉钉插件本质是 10.3 webhook 的内建消费者——选一组事件、贴一个 incoming webhook URL,worker 把事件渲染成对应平台的卡片格式;不引入任何轮询。所有集成凭证(OAuth token、webhook URL)加密存储于组织级 settings,导出与注销时按第 6 章规则处理。

## 10.6 嵌入套件(Embed Kit):把 yuMeet 装进任何网站

大量组织已经有自己的官网(实验室主页、学会网站、公司站),他们要的不是再建一个活动站,而是**把会议信息显示在自己的网页上**——最新活动列表、日程、报名按钮。嵌入套件为此提供四个接入层级,按简单程度排列;最低一层只需复制两行 HTML,不写一行后端代码。所有嵌入面只暴露**已发布的公开数据**,注册、支付、登录永远发生在 yuMeet 侧的页面/弹层里——宿主网站从头到尾接触不到任何个人信息。

| 层级 | 形态 | 适合谁 | 接入成本 |
| --- | --- | --- | --- |
| L0 Web Components | 一个 `` + 自定义元素 | 任何能编辑 HTML 的人 | 复制粘贴,约 1 分钟 |
| L1 公共只读 JSON | `/api/v1/public/*`,CORS 全开 | 想完全自控样式的开发者 | 一次 fetch |
| L2 oEmbed / iframe | 贴链接自动成卡片;iframe 自动高度 | WordPress/Notion/Ghost 等 CMS,禁脚本环境 | 粘贴一个 URL |
| L3 SDK / React 组件 | `@yumeet/sdk` + `@yumeet/react` | Next.js/React 官网,构建期取数 | npm install |

### L0:一行脚本 + 自定义元素

以 galileoxu.org 为例(其组织已在 yuMeet 上启用白标域名 `events.galileoxu.org`,见 7.6;未配自定义域名时换成实例域名即可),在任意页面粘贴:

```html
<script type="module" src="https://events.galileoxu.org/embed.js" async></script>

<!-- 即将举行的活动列表 -->
<yumeet-event-list org="galileo" limit="5" locale="zh-CN">
  <a href="https://events.galileoxu.org/galileo">查看全部活动</a>  <!-- 无 JS 时的后备内容 -->
</yumeet-event-list>

<!-- 单场活动的报名按钮:点击在 yuMeet 域的弹层内完成报名 -->
<yumeet-register-button event="evt_01jd8qz3o9wk4r"></yumeet-register-button>
```

| 元素 | 关键属性 | 展示内容 | 无 JS 后备 |
| --- | --- | --- | --- |
| `yumeet-event-list` | `org` / `limit` / `upcoming\|past` | 活动卡片列表(名称、日期、地点、状态) | 渲染插槽内的后备链接 |
| `yumeet-next-event` | `org` | 最近一场活动的单卡 + 倒计时 | 同上 |
| `yumeet-schedule` | `event` / `day` / `track` | 已发布日程(按浏览者时区渲染,原则 6) | 指向日程页的链接 |
| `yumeet-register-button` | `event` / `ticket` | 报名按钮 + 余票/候补状态;点击开 yuMeet 弹层 | 普通 `` 跳转报名页 |

**样式与主题**:组件用 Shadow DOM 隔离,默认 `theme="inherit"`——字体继承宿主 `font-family`,链接与按钮色取宿主的 `currentColor`/链接色,视觉上像宿主网站自己的内容;设 `theme="cupertino"` 则携带完整 Cupertino 观感。精调走 CSS 变量透传:宿主写 `yumeet-event-list { --yu-embed-accent: #8e44ad; --yu-embed-radius: 8px; }` 即可。深浅色跟随宿主的 `prefers-color-scheme`,或由宿主在元素上显式设 `data-theme`。**工程预算**:embed.js 零依赖、gzip 后小于 30KB、不设 cookie、不做任何跟踪(嵌入方无需为它写 cookie 同意条款);数据请求命中 L1 的公共端点与 CDN 缓存。

### L1:公共只读 JSON(自渲染)

```http
GET https://events.galileoxu.org/api/v1/public/orgs/galileo/events?upcoming=1&limit=5
GET https://events.galileoxu.org/api/v1/public/events/evt_01jd8qz3o9wk4r/schedule
```

特性:无需鉴权、`Access-Control-Allow-Origin: *`、只返回已发布内容(未发布/草稿/个人数据一概不可达,见 12.1 对象级授权);响应带 `ETag` 与 `Cache-Control: public, s-maxage=60, stale-while-revalidate=600`,静态站构建期拉取或浏览器端 fetch 均可。配合 10.4 的 JSON-LD 与 ICS,宿主页面可同时获得 SEO 结构化数据与「加入日历」能力。速率限制按 IP(公共端点独立配额),不影响鉴权 API。

### L2:oEmbed 与 iframe

标准 oEmbed 端点 `/api/v1/public/oembed?url={活动页链接}`:在 WordPress、Notion、Ghost 等支持 oEmbed 发现的编辑器里**直接粘贴活动链接**,自动展开为活动卡片。完全禁脚本的环境用 iframe:``,嵌入页通过 postMessage 汇报内容高度,配套两行初始化代码实现自动高度;`/embed/*` 路径下的页面无导航壳、允许被跨域嵌框(独立的 `frame-ancestors` 策略,与主站的禁嵌框策略分开)。

### L3:SDK 与 React 组件

`@yumeet/react` 把 L0 的四个组件封装为同名 React 组件(RSC 兼容:服务端组件直接经 `@yumeet/sdk` 取数出静态 HTML,客户端零 JS);galileoxu.org 若是 Next.js/Astro 站,构建期渲染活动列表,发布新活动后由 10.3 的 webhook 触发官网重新构建——信息展示完全静态化,快且无运行时依赖。

> **设计要点** 「非常简单」的落点在管理后台:活动的「嵌入」页为每个组件生成**可复制的代码片段 + 所见即所得预览**(选组件 → 调属性 → 复制),组织者不需要读本节任何文字。嵌入默认对所有域名开放;需要收紧时可在组织设置里配置域名 allowlist(校验 `Origin`/`Referer`,仅作展示约束而非安全边界——公开数据本就公开)。

> **对照 Indico** Indico 把「会议信息上自己官网」留给各机构自行抓 API 或 iframe 硬嵌,没有官方嵌入组件;结果是大量机构页面用截图和手工维护的 HTML 表格同步会议信息。嵌入套件把这条最常见的集成路径产品化为复制粘贴级体验,这正是原则 1(网站与系统分离)的完整形态:yuMeet 甘当无头后端,前台可以是任何人的网站。
