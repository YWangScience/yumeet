# 第 3 章 · 角色模型与信息架构

本章定义 yuMeet 的五角色模型、每个角色的首屏内容与导航树、五条关键用户旅程的逐步系统行为,以及可读 URL 的信息架构规则。角色决定界面,界面决定复杂度分配:组织者的每一个选项,都不允许出现在参会者的屏幕上。

## 3.1 五角色模型(参会者/讲者/审稿人/组织者/平台管理员)

yuMeet 的角色不是账户类型,而是**活动作用域内的上下文**。同一个身份可以在 A 活动是参会者、在 B 活动是组织者、在 C 活动同时是讲者和审稿人。角色由「组织级角色 × 活动级角色 × 细粒度能力」三层组成(能力表见第 6 章),本章只关注角色对应的**界面分屏**:每个角色进入独立的系统面,互不可见、互不干扰。

| 角色 | 作用域 | 入口路径 | 核心任务 | 体验硬指标 |
| --- | --- | --- | --- | --- |
| 参会者 Attendee | 单个活动 | 公共活动站 + `/me` | 报名、查日程、收凭证、追踪状态 | 60 秒完成报名,全程无登录墙 |
| 讲者 Speaker | 单个活动 | `/me/submissions` | 投稿、传资料、确认时段 | 投稿表单单页完成 |
| 审稿人 Reviewer | 活动内的 track | `/review` | 评分、讨论、给出结论 | 单篇评审 5 分钟内可提交 |
| 组织者 Organizer | 组织或单个活动 | `/manage` | 建会、审批、排程、群发、现场 | 5 分钟建会上线 |
| 平台管理员 Platform Admin | 整个实例 | `/admin` | 租户、配额、插件、备份、合规 | 日常运维趋零(见第 11 章) |

三条派生规则:第一,**参会者无需账户**——报名产生的是一条 registration 记录加一个不可枚举的追踪链接,账户是可选的升级(见 6.1);第二,讲者与审稿人角色由系统事件自动授予(投稿被创建、评审邀请被接受),组织者不手工维护角色名单;第三,同一人在同一 track 内同时是作者与审稿人时,利益冲突由系统强制隔离(见 4.3),而不是靠约定。

## 3.2 每个角色的首屏内容与导航树

首屏(above the fold)只放该角色**当前最可能要做的一件事**,其余内容按导航树收纳。以下逐角色定义。

### 参会者:公共活动站与 /me

公共活动站首屏是 hero 区:活动名、按浏览者时区渲染的起止时间、地点、一个主 CTA(报名 / 已报名则显示「我的票」)。报名后,首屏 CTA 被状态卡替换,状态卡即 5.5 定义的「像查快递」的进度追踪。导航树由模板包的 slots 驱动(见第 7 章),默认为:

- 活动首页(hero、议程亮点、地点)
  - 日程 `/schedule`(多轨时间表、个人收藏、ICS 订阅)
  - 讲者 `/speakers`
  - 场地与交通 `/venue`
  - 常见问题 `/faq`
  - 报名 `/register`
- 个人区 `/me`(需最低限度身份,magic link 即可)
  - 我的票(二维码、Wallet、退改)
  - 我的日程(收藏的 session)
  - 我的资料与隐私(名单 opt-in、数据导出)

### 讲者:/me/submissions

首屏是投稿列表,每条一枚状态 chip(状态机见 9.4)加一个待办 CTA——「上传终稿」「确认时段」「查看意见」。没有待办时不显示按钮,而不是显示灰色按钮。导航:投稿列表 → 单篇详情(版本历史、文件、脱敏后的评审结论)→ 我的日程时段。

### 审稿人:/review

首屏是评审队列:进度条(已完成 x / 分配 y)、按截止日排序的待评列表、一个「继续评审」按钮直接进入下一篇未完成项。导航:待评队列 → 单篇评审页(脱敏稿件、评分表单、讨论)→ 已完成列表 → 利益冲突声明页。

### 组织者:/manage

首屏是活动 dashboard,自上而下:今日待办(待审批 N 条、候补待放行 N 条、未排程投稿 N 篇,每条可点击直达)、关键指标(报名数、收入、投稿数,含 7 日趋势)、快捷操作(群发邮件、导出名单)。导航树按模块开关动态增减(见 4.1):

- `/manage/{org}` 组织层(活动列表、成员、品牌与域名、账单)
- `/manage/{org}/{event}` 活动层
  - 概览(dashboard)
  - 注册(表单、票种、审批、候补、优惠码、名单)
  - 征稿(CFP 配置、投稿、评审分配、录用流水线)
  - 日程(编排器、房间、版本)
  - 邮件(模板、群发、送达报表)
  - 现场(签到、胸牌、会场屏、公告)
  - 设置(基本信息、主题、集成、危险区)

### 平台管理员:/admin

首屏是实例健康页:各容器状态、队列积压、磁盘与备份时间。导航:租户与配额 → 用户与封禁 → 插件 → 邮件域信誉 → 审计日志 → 系统设置。自托管单租户场景下,/admin 与组织者常由同一人担任,但界面仍然分屏——运维操作不混入活动操作。

> **设计要点** 导航树的每个节点都必须回答「谁、在什么时候、来这里做什么」。回答不出来的节点删掉;两个角色都要的页面做两份视图,而不是做一份带权限开关的页面。

## 3.3 关键用户旅程

以下五条旅程是验收基准:每一步标注系统行为,实现偏离本清单即视为回归。时长指标按 P75 统计。

### 旅程 A:参会者 60 秒报名(免费活动、无审批)

1. 访客打开 `/acme/devcon-2026`。**系统:**返回 ISR 缓存页(见第 13 章),所有时间按浏览者时区渲染并标注时区名。
2. 点击 hero 区「报名」。**系统:**直接进入 `/register` 表单,不弹登录墙、不要求验证码。
3. 填写邮箱与姓名(默认表单仅此两项必填)。**系统:**邮箱输入停顿 300ms 后查重;若该邮箱已报名,就地提示「找回我的报名」并可发送追踪链接邮件。
4. 选择票种。**系统:**实时显示余量;选中即在 Redis 预占 1 个名额,有效 10 分钟(扣减时序见 13.3)。
5. 点击「提交」。**系统:**事务内创建 registration(状态 confirmed)与票据;同步返回完成页;异步任务(BullMQ)在 60 秒 SLA 内发送确认邮件,含二维码票、ICS 附件、追踪页链接 `/r/{token}`。
6. 完成页展示二维码票与「加入日历」。**系统:**提示可选保存 passkey(一次点击,SimpleWebAuthn),拒绝则不再打扰;不创建密码、不发验证邮件阻塞流程。

> **对照 Indico** Indico 的注册常要求先建终身账户、通过邮箱验证后才能填表,且确认邮件延迟并频繁进垃圾箱。yuMeet 把身份验证移到流程之后(票据自带签名 token),邮件走已验证 DKIM 的发送域并追踪送达(见 4.4)。

### 旅程 B:组织者 5 分钟建会

1. 登录 `/manage`,点击「新建活动」。**系统:**打开三步向导(见 4.1),显示步骤进度。
2. 第 1 步填名称、起止日期、时区、地点类型(线下/线上/混合)。**系统:**由名称实时生成 slug 并查重,可手改;时区默认取浏览器时区。
3. 第 2 步选外观。**系统:**默认选中 Cupertino 主题并渲染实时预览;可上传 logo、选主色,均可跳过。
4. 第 3 步点击「创建」。**系统:**创建 event(状态 draft)、默认单轨日程、默认注册表单(姓名 + 邮箱);跳转 dashboard 并显示「发布前检查清单」。
5. 按需打开模块开关(如注册、征稿)。**系统:**每个模块开启即用默认配置生效,公共站与管理导航同步出现对应入口。
6. 点击「发布」。**系统:**校验清单(时间、slug、至少一个可见页面),触发 ISR 生成公共页,返回公共 URL 与二维码;整个旅程无任何必答的高级选项。

### 旅程 C:讲者投稿

1. 讲者打开 `/acme/devcon-2026/cfp`。**系统:**展示各 track 的说明、截止时间(按浏览者时区)与投稿类型。
2. 点击「投稿」,输入邮箱。**系统:**发送含 magic link 的验证邮件(15 分钟内有效、一次性);已登录用户跳过此步。
3. 点击邮件链接回到单页投稿表单。**系统:**建立会话;表单按该 track 配置渲染(标题、摘要、关键词、作者、文件)。
4. 添加合作者并标注报告人。**系统:**每位合作者仅需邮箱;暂不发通知,提交成功后才发。
5. 上传 PDF。**系统:**直传 S3(预签名 URL),worker 异步做病毒扫描与 PDF 元数据剥离(双盲要求,见 4.3)。
6. 点击「提交」。**系统:**创建 submission(状态 submitted),向作者与合作者发确认邮件,含追踪页 `/s/{token}`;截止前可随时修改,每次修改记版本。
7. 后续状态变化(进入评审、录用、拒绝)。**系统:**每次迁移写 timeline 并邮件通知,追踪页同步更新(见 5.5)。

### 旅程 D:审稿人评审

1. 审稿人收到邀请邮件,点击「接受邀请」。**系统:**magic link 建立会话,授予该 track 的 reviewer 角色,进入 `/review`。
2. 首次进入填写利益冲突声明。**系统:**与投稿作者做机构(ROR id)与邮箱域自动匹配,命中项默认勾选,可补充手动声明。
3. 点击「继续评审」进入下一篇。**系统:**按双盲配置渲染脱敏稿件(隐藏作者、机构,文件名重写为 `submission-{id}.pdf`)。
4. 逐维度打分并写意见。**系统:**草稿每 5 秒经 Server Action 自动保存;意见分「给作者」与「仅委员会可见」两栏。
5. 点击「提交评审」。**系统:**锁定分数、更新队列进度;此后才对该审稿人开放本篇的讨论线程(防锚定)。
6. 参与讨论直至 chair 给出结论。**系统:**讨论新回复推送邮件摘要(每日合并一封,可改为即时)。

### 旅程 E:现场签到

1. 工作人员在手机/平板打开签到 PWA(`/manage/{org}/{event}/checkin`)。**系统:**首次加载后缓存名单摘要与验签公钥,支持离线运行。
2. 扫描参会者二维码。**系统:**本地验签(Ed25519,无需网络),200ms 内显示姓名与票种;重复签到显示醒目警告与上次时间。
3. 确认签到。**系统:**写入 checked_in 事件;离线时入本地队列,恢复网络后按幂等键同步。
4. 需要补打胸牌时点击「打印」。**系统:**satori + resvg 按胸牌模板渲染 PDF,推送到指定打印机队列(见 5.2)。
5. 大屏与后台看板更新。**系统:**SSE 推送签到计数与公告到会场屏,延迟目标 &lt; 2 秒。

## 3.4 URL 与信息架构设计

URL 是归档承诺的一部分(原则 7):公共 URL 一经发布永久有效,活动结束后**同一 URL** 直接呈现归档态,不做跳转、不换域名。规则如下:

1. slug 规则:`[a-z0-9-]{3,64}`,由名称自动转写生成,组织内唯一;保留字表(`manage`、`admin`、`api`、`me`、`review`、`r`、`s` 等)禁止注册为 org 或 event slug。
2. 公共路径不出现数据库自增 ID;需要定位实体时用「语义 slug + 8 位 base32 短 ID」后缀,短 ID 永不复用。
3. slug 重命名后旧 URL 永久 301,历史 slug 占用不释放。
4. 个人页(追踪、认领)使用 128-bit 不可枚举 token(base64url),不进搜索引擎(`noindex`),可由本人重置使旧链接失效。
5. 筛选、分页、tab 一律进 query string,不进 path;语言不进公共 URL,由 Accept-Language 与用户偏好决定。
6. 自定义域名(见 7.6)映射到 `/{org}` 或单个活动根,内部路径规则不变。

| 模式 | 示例 | 说明 |
| --- | --- | --- |
| `/{org}` | `/acme` | 组织主页:活动列表与归档 |
| `/{org}/{event}` | `/acme/devcon-2026` | 活动主页;年份是否入 slug 由组织者决定 |
| `/{org}/{event}/schedule` | `/acme/devcon-2026/schedule` | 日程;query 承载轨道与日期筛选 |
| `/{org}/{event}/sessions/{slug}-{sid}` | `…/sessions/swift-keynote-7g2kq4xw` | 单个 session 永久链接 |
| `/{org}/{event}/speakers/{slug}-{sid}` | `…/speakers/lin-wang-9k3mzp2a` | 讲者页(经本人 opt-in) |
| `/{org}/{event}/register` | `…/register` | 报名表单 |
| `/{org}/{event}/cfp` | `…/cfp` | 征稿说明与投稿入口 |
| `/r/{token}` | `/r/Nn4…` | 报名追踪页,个人、noindex |
| `/s/{token}` | `/s/Qx8…` | 投稿追踪页,同上 |
| `/me` | `/me` | 个人区,跨活动聚合 |
| `/manage/{org}/{event}/…` | `/manage/acme/devcon-2026/registration` | 管理后台,与公共站同域同应用 |
| `/review/{org}/{event}` | `/review/acme/devcon-2026` | 审稿人工作台 |
| `/api/v1/…` | `/api/v1/events/{id}` | 对外 REST,版本化策略见第 10 章 |

> **设计要点** 一条 URL 应当能被口头念出来、写进海报、十年后仍然可达。凡是做不到这三条的链接(个人 token 页、管理页),一律排除出搜索引擎与公开分享路径。
